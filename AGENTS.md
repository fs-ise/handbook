# Repository guide

- This is a Quarto website; most authored pages are `.qmd`, while course offerings include `.md` and `.qmd`. `_quarto.yml` defines the sidebar navigation; not every source or generated page is listed there. Edit source files, not `_site/` (rendered output). For courses, `data/courses.yml` is the canonical source for course IDs and titles, and `teaching/courses/` contains semester-specific offerings (see `teaching/new_course.qmd`).
- Render locally with `quarto render`; preview with `docker compose up` (port 4200). The compose service runs `quarto preview` in the project directory.
- The site-publishing workflow runs on pushes to `main` using Quarto 1.9.38 and Python 3.11; it smoke-renders `teaching/reports.qmd --execute` before rendering the full site. Other automation workflows may use different Python versions and dependencies. Install the base package with `python -m pip install -e .` (executed notebooks may also need `nbformat jupyter pandas matplotlib`).
- Python utilities live in `src/`; install test dependencies and run the suite with `python -m pip install -e . pytest` followed by `python -m pytest tests`. `pyproject.toml` requires Python >=3.11 and declares only the base dependencies; some utilities need additional packages such as `colrev`, `requests`, `PyGithub`, `pandas`, or `matplotlib`, as documented in their workflow or script.
- To add or update a research paper, edit its BibTeX record in `data/references.bib` and run `python src/update_papers.py` (requires `colrev`). It clears and rebuilds `research/papers/` and may also create pages in `teaching/papers/` for records tagged for teaching; review both directories' diffs. Avoid editing generated paper pages by hand.
- `data/projects.yml` is the source for `research/projects/`; `python src/generate-projects-pages.py` clears and rebuilds that output directory. For talks, `data/talks.bib` feeds `research/talks/` and `talk_places.csv`. `src/update_repositories.py` generates `assets/repos.json` and requires `GITHUB_TOKEN`; `src/research_statistics.py` generates CSV and PNG reports under `assets/reports/` and also requires `GITHUB_TOKEN`. Treat these outputs as generated rather than hand-maintained.
- `data/events.yaml` is the calendar source; `python src/update_calendar.py` generates `assets/calendar/fs-ise.ical`. AISNET and TimeEdit sync jobs reconcile upstream events and update both files; edit the YAML source, not the generated iCal file.
- `make repository-conformance` runs `python src/repository_conformance.py`. This generator updates `assets/reports/repository-conformance.json` and `teaching/_generated/repository-conformance.qmd`; do not edit either generated file by hand. It may clone/fetch course repositories and query the GitHub API; use `--offline` for local-only checking.
- `_quarto.yml` sets `execute-dir: project` and `execute.freeze: auto`; notebook execution and its frozen results are project-scoped.
