## Process

```{mermaid}
flowchart LR
    A[<a href="#announce">1. Announce the course</a><br/>4 months before] --> B[<a href="#prepare">2. Prepare the course</a><br/>1 month before]
    B --> C[<a href="#offer">3. Offer the course</a>]
    C --> D[<a href="#grade">4. Exam grading<br/>and documentation</a>]
    D --> E[<a href="#repeat">5. Repeat exam</a><br/>following term]
```

## 1. Announce the course (4 months before) {#announce}

Start: December (summer term), May (winter term)

- [ ] Canvas team: Create the course and shares the link.
- [ ] Carefully select lecture rooms (Power supply, Harvard vs. Flat, Beamer)

Deadline: mid-May (summer term), December/January (winter term)

## 2. Prepare the course (1 month before) {#prepare}

Start: March (summer term), September (winter term)

- [ ] Professor: Review `feedback.qmd`, add feedback from issues, student evaluations, and surveys, document how the feedback was addressed, and mention the addressed feedback in the first lecture.

Follow the complete [Canvas course checklist](/teaching/lms.html) when preparing the LMS course.

- [ ] Professor: Review the syllabus and programme-specific Canvas elements.
- [ ] Professor: Define the Canvas course structure.
- [ ] Professor: Prepare and organize course content in Canvas.
- [ ] Professor: Configure assignments, group sets, and rubrics where applicable.
- [ ] Professor: Define discussion and communication settings.
- [ ] Professor: Review the course using Student View.
- [ ] Professor: Ask TEL for a final link-validation and accessibility check when the course setup is complete.
- [ ] Professor: Publish the Canvas course when it is ready for students.

Deadline: April (summer term), October (winter term)

## 3. Offer the course {#offer}

Start: April (summer term), October (winter term)

- [ ] Professor (Team Assistant): Prepare the exams. Use the [exam checklist](/teaching/exams.html#preparing-the-exam).
- [ ] Add exam dates to the [calendar]({{< meta handbook.url >}}/tree/main/data/events.yaml)

## 4. Exam grading and documentation {#grade}

Grading

- [ ] Create a reminder for the deadline.
- [ ] Check whether to adjust the grades of narrowly failing exams upwards and, if necessary, lower the passing threshold in favor of students

Documentation

- [ ] Professor: Analyse the evaluations, store the files, and document the improvements (see [evaluations](/teaching/evaluations.html)).
- [ ] Professor: Document necessary changes for the following exams (e.g., unclear questions, too many questions)

Deadline: End of August (summer term), March (winter term)

Students can review their exams and grades according to the applicable examination-office process.

## 5. Repeat exam {#repeat}

Students have the possibility to repeat the exam in the following term (even if the lecture is not offered again). Registration for students in FlexNow is created by the examination office.

- [ ] Professor: Upon notification by the examination office (E-Mail: "Prüferbestellung"), create the repeat exam. Student registrations are available in FlexNow.
- [ ] Repeat relevant steps of *Exam grading and documentation* (step 4).

Students can review their exams and grades according to the applicable examination-office process.
  • Update yaml-header information.
  • Update github pages, e.g., dates on the project page (e.g., example).
  • The overview, evaluation and improvements are updated automatically.

Scheduling of courses

The scheduling department (individuals responsible for specific degree programs) contacts me (with preferences gathered via TimeEdit/Google Forms). I then receive a proposed schedule (I must manually check and resolve conflicts between programs; if necessary, clarify with the scheduling department or speak directly with colleagues). Ensure that module coordinators list me as the instructor (otherwise invitations will be sent to the wrong person).

New module

New modules and teaching sessions must be created according to the applicable Frankfurt School programme-management process. Confirm the responsible system, approvals, and deadlines with the programme team before announcing a new module.

Coordination
